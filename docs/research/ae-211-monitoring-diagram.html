Monitoring every research run

AWS Batch on EC2 reviews approved evidence from registered EC2 workloads. Each reviewer preserves intermediate artifacts in S3 and sends all findings directly to Slack. Action enforcement and Phase II reliability are future extensions.

Passive monitoring. Separate EC2 reviewers have no tools or authority to intervene. Existing AWS resources and target security groups stay untouched. Missing access and telemetry are coverage gaps.

All findings are surfaced. Every reviewer sends its own Slack webhook notification with severity, confidence, and an authenticated S3 notes link. There is no shared notifier.

Review artifacts and DynamoDB

Private versioned S3 retains the exact prompt, scrubbed evidence, model response when available, model metadata, report, and manifest with object versions and hashes. Slack links require AWS login. DynamoDB holds conditional leases, the latest workload profile, delivery state, and atomic inference reservations. Large artifacts stay in S3; TTL only cleans up delivered rows.

Read-only access and operating limits

Target-side enforcement uses a dedicated inspection account, forced internal-sftp -R, a root-owned chroot with scrubbed exports, and no shell, sudo, PTY, or forwarding. The reviewer pins the host key and reads at most eight explicit files, 64 KiB each, with a 512 KiB combined evidence bound. No recursive scans or commands. Reads still consume resources and SSH may update authentication/access logs.

Five-minute discovery uses overlapping 30-minute evidence windows. First reviews map the workload; subsequent reviews reuse profiles and focus on existing source IDs. Recommendations never authorize new access. Existing Langfuse and CloudWatch sources are opt-in; no network sensor installation is implied.

Monitoring-only credentials live in the existing account’s SSM Parameter Store. Native read-only Langfuse credentials are not assumed available; dedicated keys or a read-only proxy must be supplied. Batch/Scheduler terminal failures go to operations SQS and a CloudWatch alarm with human ownership.

Future extensions

Synchronous action checks and inspect-orchestrator/Scout reliability analysis require separate authorization, implementation, and validation. Neither is represented as deployed protection.

Mermaid source and text alternative

Scheduled discovery submits one Batch EC2 review per registered target/window. The job collects evidence, preserves artifacts, updates DynamoDB, and sends its own Slack message.
