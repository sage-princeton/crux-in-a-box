Long-Horizon Autonomous Research-Agent Harness

A self-governing scaffold that lets a single AI agent run unattended for days to produce a peer-review-grade research paper: it supplies a binding constitution, a pre-registered audit trail, playbooks, a heartbeat sweeper, and a strictly non-blocking operator interface so the agent keeps deciding and shipping evidence-backed work without waiting on a human.

How to read this page

Start with The big picture to see a full run as a single flow. Then skim the Components and walk The run, phase by phase. The Cross-cutting systems are always-on machinery referenced throughout. Inline badges mark who acts (operator / agent / subagent), where a gate must pass, where a fork branches out, and which mechanisms are new.

The organizing principle: Components are files (nouns); The run is the process (verbs); Cross-cutting systems are rules that hold in every phase. So the same name — e.g. the headline-substance gate — appears once as a file/certification (a Component), again as a step that runs it (in The run), and again as a rule (Cross-cutting). When a phase step names a component, its Components card is the definition.

Key terms (read these first)
  • Decision tiers 1 / 2 / 3 — authority levels: Tier 1 act-and-log, Tier 2 logged memo + proceed on a branch, Tier 3 blocking operator contact (defined in the Decision tiers panel).
  • Regime B — the heartbeat as a sweeper (safety-net clocks) rather than an engine (regimes A/C, event-driven or single-loop, are the alternatives it was chosen over).
  • Falsifier — a pre-registered trigger condition that would prove a claim wrong, declared before its first experiment.
  • Claim ledger — the append-only record of every narrowing of the headline; a claim may not shrink without a triggered falsifier or logged cost argument.
  • Headline-substance gate — the Milestone-1 check that the locked headline is non-vacuous and not true-by-construction before any drafting.
  • Scout-DEPTH — the settlement rule that only a clean FAIL/PASS scout verdict may kill or promote a candidate (not an ambiguous/under-powered one).
  • Underclaim audit — the inverse review that looks for the strongest claim the evidence licenses but the text omits or hedges.
  • Compress-then-expand — drafting that locks a compressed narrative first, then expands it stage by stage.
  • Crunch block — the tightened cadence (10-min beats, every beat moves a deliverable) when a milestone is <24h out.
  • Footgun — a known sharp edge of the runtime/tooling logged in TOOLS.md so the agent does not step on it.
  • NeurIPS-style — a hostile-fair, page-cited conference-reviewer format used for the blind rounds.
  • §-codes — review regimes defined in the Review regimes table: §1 hostile section review, §1b underclaim audit, §2a internal blind rounds, §2b external reviews, §2c accompanying final review, §3 brief-fidelity review.

The big picture

A whole run as one flow, read as a top-to-bottom snake: row 1 runs left → right, then a curved arrow drops down the right edge into row 2, which runs left → right again. Numbered badges 1–8 on each node give the order. Two branches are called out: the ⛔headline-substance gate that must pass before any drafting, and the ⑃central-claim-rejection fork that routes the review loop back to "advance next candidate / re-scope".

The run, phase by phase

An ordered walk through a run. Each phase shows who acts; each step shows its gates and forks as inline badges, and flags newly-added steps. Phases are expanded by default — collapse any you don't need.

  1. 0. Operator setup & launch ◆operatorProvision the machine, resolve task placeholders, verify accounts and telemetry, then send PROMPT.md and step back.

    • Provision device

      Run setup-device.sh to spin up the EC2 instance and bootstrap desktop+VNC, OpenClaw, Telegram, monitoring, telemetry, services, and the workspace; openclaw.json is auto-configured.

      ⛔Gate: AWS CLI v2 authenticated + ssh/scp/jq present locally

    • Resolve task-specific placeholders

      Fill GITHUB_USER, PAGE_BUDGET, SNAPSHOT_TIMES, CLOUD_SPEND_LIMIT, EXTERNAL_REVIEWERS, VENUE, DELIVERABLE_TOOLCHAIN, PREFLIGHT_COST/HOURS across TOOLS.md, USER.md, HEARTBEAT.md, gate_artifact.sh, AGENTS.md, review.md.

    • Verify accounts & telemetry

      Operator confirms GitHub gh auth, Telegram pairing, email CLI, external-reviewer logins, and cloud quotas, and that telemetry_costs.py runs against live telemetry with caps stated in BRIEF.md.

      ⛔Gate: all accounts working now and telemetry script runs against live data⑃Fork: broken reviewer login mid-run later becomes a Tier-3 block

    • Send PROMPT.md

      Send PROMPT.md as the first message; do not recreate the intentionally-absent files (SOUL.md, IDENTITY.md, SELF_KNOWLEDGE.md, BUDGET.md, SPRINT.md).

      ⛔Gate: first message sent
  2. 1. Hour-0 planning & pre-registration ●agentVerify the environment, restate the goal, register brief constraints, lock the headline + falsifiers, and write the milestone table — all logged as the first Tier-2 memo.

    • Hour-0 environment verification

      Verify every fact in TOOLS.md against the live environment and correct the file where reality differs; catches stale placeholders left at defaults.

      ⛔Gate: TOOLS.md reconciled with live environment

    • Restate goal & register brief

      Write the PLAN.md Goal paragraph; register every BRIEF.md requirement and prohibition as a REGISTRY.md Brief-constraints row with a checking mechanism.

      ⛔Gate: logged as the first Tier-2 memo within ~2h of reading BRIEF.md

    • Build candidate portfolio

      Fill 2-3 ranked candidates spanning the design space, each with cheapest scout, kill criterion, promotion criterion, and status.

    • Lock headline claim & falsifiers

      Lock base + stretch headline; register a pre-registered falsifier in REGISTRY.md for each method claim before its first experiment; freeze definitions as JSON in locks/.

      ⛔Gate: falsifier declared before its experiment runs; no tautological headline accepted at registration⑃Fork: vacuous/true-by-construction headline rejected → Stuck/Pivot

    • Write milestone table

      Define 3-6 milestones, each with an absolute deadline and a gate command (every gate includes the brief-fidelity review).

      ⛔Gate: part of the first Tier-2 memo
  3. 2. Candidate exploration / scouts ▲subagentRun the cheapest scout per candidate to settle the portfolio before any headline commitment.

    • Run cheapest scout per candidate

      Spawn scouts (≤3 in flight, each with a budget and verdict bins) to test each candidate against its pre-registered kill/promotion criterion.

      ⛔Gate: committing to a headline requires clean scout results from at least two candidates⑃Fork: mechanism-level failure → advance the next portfolio candidate

    • Settle candidates (scout-DEPTH) ✦ new

      A candidate is killed or promoted only by a scout returning a clean FAIL/PASS against its pre-registered criterion; an AMBIGUOUS / MALFORMED / single-seed / under-powered scout does NOT settle it.

      ⛔Gate: clean FAIL/PASS verdict against the pre-registered criterion⑃Fork: inconclusive scout → deepen or re-run before narrowing the headline
  4. 3. Milestone 1 — skeleton & headline-substance gate ●agentStand up the deliverable skeleton in the target format and clear the headline-substance gate before any drafting begins.

    • Build deliverable skeleton

      Verify env, build a deliverable skeleton that compiles in the target format, and confirm plan/falsifiers are registered with the page-budget gate live.

      ⛔Gate: skeleton compiles in target format; plan/falsifiers registered

    • Headline-substance gate ✦ new

      Add the HEADLINE-SUBSTANCE line to REGISTRY.md and run REQUIRE_HEADLINE_SUBSTANCE=1 scripts/gate_artifact.sh on the skeleton.

      ⛔Gate: locked headline clears non-vacuous=yes (and not-by-construction=yes, certified by an independent subagent, if negative/impossibility)⑃Fork: headline fails certification → Stuck/Pivot, not drafting
  5. 4. Drafting + section reviews + figures ●agentWrite compress-then-expand, building figures and re-deriving every load-bearing number, with hostile section reviews and an underclaim counter-force at each cycle.

    • Compress-then-expand drafting

      Compressed narrative (the lock) → intro outline → full outline → results/figures → first draft → iterative editing; each stage gets a hostile + underclaim pass before expanding.

      ⛔Gate: Stage-5 first-draft prose may not begin while any headline number lacks its REGISTRY.md row

    • Hostile section review (§1)

      A fresh isolated reviewer per section version hunts reasons to reject; the agent triages SHIP/DEFER/ESCALATE (the reviewer only grades) and loops review→fix→review.

      ▲subagent⛔Gate: two consecutive reviews with no MAJOR = section stable

    • Underclaim audit (§1b) ✦ new

      An inverse audit runs once per drafting cycle per load-bearing section (and once on the full draft before endgame) for the strongest claim the evidence licenses; demotions cross-checked against the Claim ledger.

      ▲subagent⛔Gate: any unbacked demotion gets a forcing-evidence ledger row or is reverted

    • Figure iteration loop

      Write a 3-line spec.md, plot from cached artifacts only, render then LOOK with the vision tool, and run a two-pass blind takeaway test.

      ⛔Gate: two consecutive blind passes match the spec's takeaway = figure done

    • Number sweep

      Re-run each Audited-numbers derivation script and confirm prose matches, updating last-verified.

      ⛔Gate: the agent-extended number-consistency sweep (a gate_artifact.sh TODO added during the run) passes before every review round and milestone gate⑃Fork: mismatch blocks the gate until fixed
  6. 5. Endgame — internal blind review ▲subagentAfter the mechanical gate passes, run isolated NeurIPS-style blind rounds to a binding stopping rule, with a mechanism-level fork for recurring central-claim rejection.

    • Mechanical gate (§2)

      gate_artifact.sh runs before every round checking page budget, placeholder sweep, internal-vocab, the deanonymize grep (the {{AGENT_NAME}}/{{OPERATOR_NAME}} tokens), and leaked internal-paths (repo/org-style paths like runs/exp_, code/scripts/, LOG.md, REGISTRY.md, locks/). The registered-number-consistency sweep here is the agent-extended check added during the run.

      ⛔Gate: gate_artifact.sh must pass before blind rounds begin

    • Internal blind rounds (§2a)

      An isolated reviewer gets only the PDF path + verbatim spawn block (no round numbers, prior verdicts, findings, or streak context) and returns a hostile-fair review and ledger row.

      ⛔Gate: stop after 2 consecutive clean rounds or at round 6 (round 7 is a contract violation → §2b)⑃Fork: identical verdict two rounds = zero-information → §2b

    • Central-claim rejection fork ✦ new

      A central-claim rejection (headline named unsound/circular/tautological/vacuous at Weak Reject or below) recurring across ≥2 rounds bars the next round; it is mechanism-level and enters Stuck/Pivot.

      ⛔Gate: an honest WEAK_ACCEPT (significance/presentation-only complaints) still ships at cap-6⑃Fork: recurring central-claim rejection → Stuck/Pivot, default = advance next portfolio candidate
  7. 6. Endgame — external review (gated milestone) ◆operatorSubmit to external reviewers as a required milestone, then do one fix pass and rebuild.

    • External reviews (§2b)

      Submit to every external reviewer in BRIEF.md/TOOLS.md Accounts respecting quotas/ordering (paid single-shot last); triage, one fix pass, rebuild.

      ⛔Gate: final-milestone REQUIRE_EXTERNAL_REVIEWS=1 gate_artifact.sh checks an artifact exists in reviews/external/
  8. 7. Completion ●agentRun one last accompanying blind review and ship it verbatim with the completion report.

    • Accompanying final review (§2c)

      One last internal blind round under §2a ships with the deliverable verbatim plus a ≤6-line author annotation on what was fixed and what was not.

      ⛔Gate: runs after externals complete

    • Completion report

      Send the completion report (tag/SHA, deliverable path, final-review verdict, external outcomes, repro command, what to do with more time) to the operator. The report itself is the long-standing Tier-3/USER.md completion message; only the under-spend fork attached to it is new.

      ⛔Gate: deliverable passed full review hierarchy + final gate⑃ ✦Fork (new): under-spend (>50% deadline AND >40% budget left) routes back to advance a candidate / strengthen a claim, not finish

Cross-cutting systems

Always-on machinery referenced by every phase. Expand a panel for its details and its checklist.

End-of-Turn Contract (four states)

Every main-session turn must end in exactly one of four forward states; a turn ending in none is a failed turn and "yield with nothing scheduled" does not exist. Before yielding it updates PLAN.md work-queue rows and overwrites the ≤10-line state capsule.

  • LAUNCH — start a background job under a pre-registered LOG.md branch protocol + harvest cron
  • DELEGATE — put subagents in flight with deliverable paths and budgets
  • MEMO — log a Tier-2 decision and act on a branch
  • MILESTONE — pass a gate script and execute the next milestone's first action
  • State-capsule + work-queue update before yielding
Decision tiers (1 / 2 / 3)

A three-tier authority model so the dominant time loss in long-horizon work — unmade decisions — never happens; "escalate then wait" is banned by name.

  • Tier 1 — Act and log within delegated scope (no notification beyond snapshots)
  • Tier 2 — Logged decision memo for anything changing the contribution, a lock, or the schedule (critic pass if it changes the contribution); proceed immediately on a branch
  • Tier 3 — Blocking operator contact only for a broken external resource (after documented debugging) or the completion report
  • Banned anti-patterns: escalate-then-wait, maturation horizon, ad-hoc pings, speculative pre-commitment
Heartbeat regime B (sweeper, not engine)

A 30m skipWhenBusy sweeper with per-task interval clocks acting as safety nets while events (self-chains, subagent completions, memo defaults) do the actual forward work; if a self-chain or in-flight subagent already owns the next action the beat does hygiene only.

  • harvest-check 30m — execute pre-registered branches, inspect +50% subagents, reconcile capsule/work queue
  • git-hygiene 60m — commit+push dirty tree
  • milestone-clock 3h — re-scope, crunch block, or under-spend memo; never silently slip
  • resource-check 4h — threshold ladder on the deduplicated telemetry figure
  • blocker-recheck 6h — re-test Tier-3 blockers, merge/revert waiting memo branches
  • Two fixed-time daily Telegram snapshots (replace all ad-hoc pings); HEARTBEAT_OK if nothing needs attention
Evidence rules

Truth is enforced mechanically: a number with no artifact is treated as fabricated, and every load-bearing statistic flows artifact → re-derivation script → prose with a registry row.

  • Artifact-or-it-didn't-happen (every report ends with an Evidence Block)
  • Code-as-fact (committed re-derivation script + Audited-numbers row per stat)
  • Read-before-summarize
  • Parent verification duty (spot-check ≥1 artifact before acting on a report)
  • Both sides of every headline (success metric + false-alarm/cost metric)
  • Claimed mechanisms get ablations
  • Symmetric claim discipline (no shrinking without a triggered falsifier; hedging = overclaiming)
Resources / cost threshold ladder

Spend is measured only by scripts (telemetry_costs.py deduplicated by responseId; AWS cost-and-usage for cloud), never hand-estimated, and gated by a pre-flight cost gate and an escalating ladder.

  • Pre-flight cost gate for any dispatch over the per-dispatch $/compute threshold (default $50 / 2h)
  • 70% of any cap — consolidate, no new gated-size dispatches without a Tier-2 memo
  • 90% of any cap — Tier-2 finish-under-cap memo
  • Breaching a cap is Tier 3
  • Time calibration: every launch records predicted wall-clock; every harvest logs predicted vs actual
Subagent economics & delegation

One unit of work per subagent assuming zero ambient context; chain or parallelize rather than write omnibus briefs, and harvest under a mandatory checklist.

  • Spawn for work bigger than a few tool calls; never for a <10-line diff (inline it)
  • Default ≤3 in flight, each with a wall-clock budget
  • Preempt/re-scope at +50% overrun
  • Subagents receive only AGENTS.md + TOOLS.md + the spawn prompt
  • Reviewers isolated, never forked (context bleed = contamination)
  • Harvest: spot-verify one artifact, check fired (not narrated) verdict bin, never copy numbers into prose, execute branch protocol, commit
Git & state discipline

The workspace stays committable so the operator can watch passively via git log, LOG.md, and the state capsule.

  • Background experiments launch with nohup → runs/<exp>/out.log + a pid file recorded in the capsule
  • Branch protocol (PASS→X / PARTIAL→Y / FAIL→Z) appended to LOG.md before any job launch
  • Gate-commit tagged at each milestone
  • git-hygiene heartbeat commits+pushes the dirty tree
  • Telegram crons use sessionTarget:main + systemEvent + wakeMode:now (footgun)
Red lines

Hard prohibitions that never relax under time pressure.

  • Never exfiltrate operator private data
  • Prefer trash over rm
  • Inspect-and-merge schedulers/configs before changing
  • Speed never justifies fabrication — evidence rules do not relax under deadline
  • Never manufacture a blocker out of a decision; operator instruction, if given, wins and is logged verbatim
Stuck/Pivot failure levels

On a tripwire the agent writes a Stuck/Pivot memo, classifies what broke, spawns one critic per option (30-45m, no new experiments), and decides within one heartbeat — a procedure that ends in a decision, not a wait.

  • Quantitative tripwires: same blocker >2h, or 3 failed attempts
  • Qualitative tripwires: ≥2-round central-claim rejection, DIVERGED brief-fidelity verdict, or vacuous-falsifier headline (polishing/datasets/narrowing does NOT clear these)
  • Implementation-level → fix and rerun
  • Mechanism-level (premise broke) → advance the next portfolio candidate, do not local-repair
  • Question-level (portfolio exhausted) → Tier-2 re-scope memo with brief-fidelity review; full restart is last resort
Crunch block

Near a milestone the cadence tightens and every beat must move a deliverable.

  • Triggered when the next milestone is <24h out (restored afterward)
  • Heartbeat cadence drops to 10 min
  • No-op heartbeats forbidden — each beat moves a deliverable, dispatches/harvests a subagent, or escalates a named blocker
  • Contact limited to scheduled snapshots plus hard environment failure
  • Cut scope at any beat where the trajectory misses the milestone
